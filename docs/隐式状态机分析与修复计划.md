## 二、逐项详细分析与修复方案

### SM-01：插件主生命周期与双源配置状态机
- **涉及文件**：`src/plugin/plugin-lifecycle.ts`、`src/plugin/plugin-lifecycle-settings-bridge.ts`、`src/services/floating-text/floating-text-storage.ts`
- **隐式状态**：
  - 加载/卸载状态（无显式 `unloaded` 标志）
  - 成对活动文档游标 `currentDocId` + `currentProtyle`
  - 本地持久化 `menuState` 与外部托管 `managedAiConfig`
- **隐藏问题**：
  1. `onload()` 在 `await loadDocMenuRegistrationState()` 期间若触发 `onunload()`，后续仍会绑定事件、手势和剪贴板轮询，导致卸载后资源泄漏。
  2. `updateMenuState()` 连续修改设置时直接并发调用 `saveData`，可能因 I/O 乱序导致旧快照覆盖新状态。
  3. `onunload()` 未重置 `memoryConfigCache`、`rangeSelectionObserverManager` 与动作运行器。
- **修复建议**：
  - 增加生命周期守卫（`isUnloaded` / generation token），在 `onload` 的 `await` 后立即中止。
  - 为 `persistDocMenuRegistrationState()` 增加写队列串行化（仅落盘最新快照）。
  - 在 `onunload()` 中补全 `actionRunner.dispose()`、`rangeSelectionObserverManager.deactivate()` 与缓存复位。

### SM-02：前/后台动作互斥与 Busy 遮罩状态机
- **涉及文件**：`src/plugin/action-runner.ts`、`src/plugin/action-runner-export-handlers.ts`、`src/plugin/key-info-controller.ts`
- **隐式状态**：
  - 前台互斥锁 `isRunning`
  - 嵌套 Busy 计数 `busyDepth`（`0 <-> 1` 驱动全局遮罩显隐）
  - 后台任务表 `backgroundTaskKeys: Map<string, number>` 与 Dock 运行中动作集合 `runningDocActionKeys`
- **隐藏问题**：
  1. `askConfirmWithVisibleDialog()` 弹出确认框前仅调用一次 `trackBusy(false)`；若 handler 在弹窗前多次调用 `setBusy(true)`（`busyDepth >= 2`），遮罩不会消失并会遮挡确认弹窗造成死锁。
  2. `import-keymap` 仅监听 `<input type="file">` 的 `change` 事件；用户在文件选择器中点击取消时 Promise 永不 settle，导致 `isRunning = true` 和遮罩永久卡死。
  3. `ActionRunner` 按 `${action}:${docId}` 隔离后台任务，而 `KeyInfoController.runningDocActionKeys` 仅按 `ActionKey` 的 `Set` 存储；同一动作在两篇文档并行执行时，先结束的任务会提前清除按钮运行态。
  4. `runActionInBackground()` 中 handler 返回 `{ ok: false, message }` 时未统一向用户提示，且缺少 `dispose()` 清理状态。
- **修复建议**：
  - `askConfirmWithVisibleDialog()` 弹窗前保存当前 `busyDepth` 并临时归零以隐藏遮罩，确认后再按原深度恢复。
  - `import-keymap` 监听 `cancel` 事件与窗口重新聚焦后的兜底检查，保证用户取消文件选择也能正常 settle。
  - `KeyInfoController` 对后台运行态改为引用计数 `Map<ActionKey, number>`，归零时才移出 `runningDocActionKeys`。
  - 为 `ActionRunner` 补齐后台失败结果提示与 `dispose()`。

### SM-03：关键内容面板、滚动锁与跳转导航状态机
- **涉及文件**：`src/plugin/key-info-controller.ts`、`src/ui/key-info-dock.ts`、`src/plugin/key-info-navigation.ts`、`src/ui/key-info-dock-doc-actions.ts`
- **隐式状态**：
  - `refreshGuard` + `readonlySyncGuard` + `loading`/`isRefreshing` + `keyInfoDocId`
  - `scrollLock` + `restoringScroll` + `scrollState` + `pendingRestoreFrames`/`pendingRestoreTimeouts`
  - `keyInfoJumpId` + 6 个固定延迟定时器 `[80, 180, 320, 500, 800, 1200]`
  - `WeakMap` 维护的折叠/搜索/拖拽状态，以及按钮局部 `.finally()` spinner 操作
- **隐藏问题**：
  1. `restoringScroll` 为单一布尔值：连续两次 `scrollListTo()` 时，首个 `rAF` 回调会提前清掉标志，使第二次程序滚动触发的 `scroll` 事件被误判为用户滚动并解除 `scrollLock`。
  2. `scheduleCenterAfterLoad()` 固定派发 6 个定时器，在首次定位命中目标块后不取消后续定时器，1.2 秒内会反复拉回视口并重复闪烁，且无 `destroy()` 清理入口。
  3. `refresh()` 在 `await getDocKeyInfo` 前捕获的 `currentState` 快照，在异步恢复后可能已滞后。
  4. `buildActionButton()` 内 `result.finally(() => setActionButtonRunning(button, false))` 与 `KeyInfoController.setDocActionRunning()` 形成双轨控制。
- **修复建议**：
  - 将 `restoringScroll` 改为计数守卫（`restoringScrollCount`），`scroll` 消费 1 次或 `rAF` 兜底归零时各自配对减 1。
  - `scheduleCenterAfterLoad()` 改为单链式定时器并在首次定位成功后立即停止，增加 `destroy()` 取消未执行定时器。
  - `refresh()` 在 `await` 之后重新读取 `this.keyInfoDock.getState()`。
  - 移除按钮级局部 `setActionButtonRunning` 竞态写，统一以 `runningDocActionKeys` 为单一数据源。

### SM-04：动态大纲、Doc Popover 与剪贴板面板状态机
- **涉及文件**：`src/plugin/dynamic-outline-controller.ts`、`src/ui/dynamic-outline/dynamic-outline-view.ts`、`src/ui/dynamic-outline/dynamic-outline-doc-popover.ts`、`src/ui/dynamic-outline/dynamic-outline-clipboard-batch.ts`
- **隐式状态**：
  - `viewMode`、flyout 展开仅靠 `.is-open` CSS 类、`isPinned`、`isDropdownOpen`、`isComposing`、`closeTimer`
  - `debounceTimer`、`refreshRequestId`、`recentDocsRequestId`、`lastDocId`
  - Popover 的 `pendingPopoverRow`/`hasEnteredPopover`/`hoveredRows` + 三套定时器集合
  - 剪贴板批量态 `isClipboardBatchMode`、`selectedClipboardIds`、`lastBatchAnchorId`
- **隐藏问题**：
  1. `clipboard` 模式下，`searchInput` 的 `keydown`（`ArrowDown`/`ArrowUp`/`Enter`）未覆盖剪贴板条目，错误读取了 `filteredItems.length`（大纲条目），按 `Enter` 会误触发大纲跳转。
  2. `searchInput` `blur` 内的 `setTimeout(..., 150)` 未纳入 `destroy()` 清理。
  3. `DynamicOutlineController.mount()` 中点击回调闭包捕获了首次 `mount` 的 `protyle` 参数；同一 `protyleElement` 更新时未刷新引用；`destroy()` 未递增 `refreshRequestId`/`recentDocsRequestId`，`refreshClipboard()` 也无 generation guard。
  4. `dynamic-outline-clipboard-batch.ts` 批量删除确认后未 `await onClipboardDeleteBatch` 即退出批量态。
  5. `dynamic-outline-doc-popover.ts` 同时维护 `rowPopoverTimers` 数组与 `rowHoverTimers`/`rowCloseTimers` 两个 `Map`。
- **修复建议**：
  - 补全 `clipboard` 模式键盘导航，将 `flyout` 显隐与 `blurTimer` 显式管理并在 `destroy()` 中清理。
  - `DynamicOutlineController` 接入 `createGenerationGuard()` 覆盖 `refreshData`、`refreshOpenDocs`、`refreshClipboard`，并在 `destroy()` 时 `invalidateAll()`；点击回调改为读取动态 `activeProtyle`。
  - 精简 `dynamic-outline-doc-popover.ts` 冗余定时器存储，批量删除等待异步回调成功后退出批量态。

### SM-05：桌面剪贴板监听与防抖落盘状态机
- **涉及文件**：`src/services/clipboard-monitor.ts`
- **隐式状态**：`loaded`、`running`、`isPolling`、`pollTimer`、`saveTimer`、`lastPolledSignature`、`suppressedSignature`
- **隐藏问题**：
  1. `start()` 在 `await this.pollOnce()` 后未检查 `if (!this.running)`，若首轮轮询期间调用 `stop()`，仍会启动 `setInterval` 形成僵尸轮询。
  2. `ensureLoaded()` 在 `loadData` 完成后才置 `loaded = true`，并发调用会重复读盘并相互覆盖 `this.items`。
  3. `suppressedSignature` 单槽位容易被连续内部写剪贴板覆盖，或未消费时残留误吞后续真实复制。
- **修复建议**：
  - 引入 `startGuard = createGenerationGuard()` 与 `loadPromise` 复用；每次 `await` 后校验守卫与 `running`。
  - 将 `suppressedSignature` 替换为带消费/过期窗口的抑制机制（或单次写入在 `copyItem`/`copyMergedItems` 时直接记录消费）。

### SM-06：鼠标手势识别与设置录制状态机
- **涉及文件**：`src/core/gesture-recognition-core.ts`、`src/ui/gesture-capture.ts`、`src/plugin/mouse-gesture-controller.ts`、`src/ui/plugin-settings-gesture.ts`
- **隐式状态**：`GestureRecognizer`（3 阶段）、`createGestureCapture`（`bound`、`dragging`、`suppressNextContextMenu`、`trailFrameId`）、控制器（`executing`、`suspended`）、设置面板（`recording` + `escHandler`）
- **隐藏问题**：
  1. `createGestureCapture.unbind()` 在 `dragging === true` 时未调用 `finishDrag(false)`，导致状态、rAF 和 `suppressNextContextMenu` 残留。
  2. `mouseGestureController.setSuspended(true)` 未取消正在进行的划动，松手仍可能触发动作。
  3. `createGestureSettingsPanel` 在录制期间关闭总开关时未调用 `finishRecording()`，全局捕获与 Esc 监听未解绑。
- **修复建议**：
  - 为 `createGestureCapture` 增加 `cancel()` 并在 `unbind()` 时调用 `finishDrag(false)`。
  - `setSuspended(true)` 时调用 `capture.cancel()`；关闭手势开关时若正在录制先执行 `finishRecording()`。

### SM-07：悬浮文本窗口多端宿主与内部 UI 状态机
- **涉及文件**：`src/services/floating-text/floating-window-adapter.ts`、`src/services/floating-text/floating-window-fallback.ts`、`src/services/floating-text/floating-window-pip-events.ts`、`src/ui/floating-text/floating-window-client-script.ts`
- **隐式状态**：4 级降级宿主实例；窗口内 `isPinned`、`isMarkdown`、`isSearchOpen`、`selectedCandidateIndex`、`.ft-popover-open`、`isDragging`、`resizeTimer`、`opacityDebounceTimer`
- **隐藏问题**：
  1. `floating-window-client-script.ts` 与 `floating-window-pip-events.ts` 中，搜索栏打开状态下切换视图（`toggleViewMode` / `Ctrl+M`）会直接显示正文/预览区域而不隐藏搜索结果页，造成 UI 叠层。
  2. `floating-window-adapter.ts` 固定写入单一临时 HTML 文件且使用 `ready-to-show` + `setTimeout(..., 60)` 双路径关闭前窗，60ms 内连续打开会相互覆盖与误杀，且 `win.on("close")` 未清除 `resizeTimer`。
  3. `openInAppFloatingFallback()` 打开的 Dialog 实例未被跟踪，`disposeFloatingWindowHostGlobals()` 卸载时不会关闭已打开的应用内降级窗。
- **修复建议**：
  - `toggleViewMode()` 在 `isSearchOpen` 时先关闭搜索状态（或仅更新模式状态与按钮提示而不直接覆盖搜索面板显隐），与 `closeSearchBar()` 协同。
  - Electron 窗口 `close` 时清除 `resizeTimer` 与兜底展示 timer；临时文件名按序号生成并在创建新窗时清理旧残留；跟踪 `currentFallbackDialog` 并在 `disposeFloatingWindowHostGlobals()` 时关闭。

### SM-08：范围选择 DOM 观察与轮询加载状态机
- **涉及文件**：`src/plugin/action-runner-select-range-handlers.ts`
- **隐式状态**：单例 `RangeSelectionObserverManager`（`activeRoot`、`activeTargetSet`、`observer`、`scrollHandler`）+ `ensureRangeBlocksLoadedInDom` 轮询循环
- **隐藏问题**：
  1. `RangeSelectionObserverManager` 激活后没有任何自动退出入口（点击编辑区取消选择、切换文档、插件卸载均不调用 `deactivate()`），导致 `MutationObserver` 持续运行甚至锁死选中态高亮。
  2. `ensureRangeBlocksLoadedInDom()` 无并发守卫，连续两次范围选择会并发争夺 `scrollTop`。
- **修复建议**：
  - 为 `ensureRangeBlocksLoadedInDom` 引入 generation 守卫；在 `RangeSelectionObserverManager` 激活期间监听编辑器 `mousedown`/`keydown` 退出选区，并在文档切换与插件 `onunload()` 时调用 `deactivate()`。

### SM-09：SQL 元数据探测单次初始化状态机
- **涉及文件**：`src/services/key-info-query.ts`
- **隐式状态**：`spanColumnsLoaded` + `spanOrderColumn`
- **隐藏问题**：`spanColumnsLoaded = true` 发生在 `await sql(...)` 之前，并发首次请求会读到未就绪的 `null`，首次短暂失败则会永久禁用列探测。
- **修复建议**：改用 `spanOrderColumnPromise` 缓存进行中的 Promise，异常时置空允许后续重试。

### SM-10：交互式弹窗局部并发状态机
- **涉及文件**：`src/ui/better-titles-dialog.ts`、`src/ui/dialogs.ts`、`src/services/request.ts`
- **隐藏问题**：
  1. `openBetterTitlesDialog()` 仅禁用被点击的单个 `replaceBtn`，未在提交期间或 `setLoading(true)` 期间互斥其他行与“重新生成”按钮。
  2. `openDedupeDialog()` 切换 `keepEarliestSwitch` 时重置全部勾选状态。
- **修复建议**：`openBetterTitlesDialog` 增加统一 `busy` 状态控制全部按钮；`openDedupeDialog` 在切换保留策略前可保留用户意图或明确重置并同步按钮可用态。
